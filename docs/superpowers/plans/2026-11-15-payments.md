# Async Payments Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать сервис асинхронных платежей с transactional Outbox, безопасными webhook и тремя попытками до DLQ.

**Architecture:** API сохраняет Payment и Outbox одной транзакцией. Consumer-процесс запускает один обработчик и отдельный relay; повторные попытки и финальная отправка в DLQ также проходят через Outbox. Результат оплаты фиксируется до webhook, а стабильный event_id позволяет получателю отсекать дубли.

**Tech Stack:** Python 3.12+, uv, FastAPI, Pydantic v2/pydantic-settings, SQLAlchemy 2 async/asyncpg, PostgreSQL, FastStream/RabbitMQ, aiohttp, Alembic, pytest, Ruff, mypy, Docker Compose.

**Spec:** `docs/superpowers/specs/2026-11-15-payments-design.md`

## Global Constraints

- Платёжный шлюз остаётся эмулятором: 2–5 секунд, 90% succeeded / 10% failed; результат стабилен по payment_id.
- Статусы оплаты только pending, succeeded, failed; сбой webhook не меняет результат оплаты.
- Всего **три попытки**, включая первоначальную; задержки по умолчанию 2 и 4 секунды.
- Все HTTP endpoints защищены `X-API-Key`; POST требует `Idempotency-Key` длиной 1–128.
- NUMERIC(18,2), RUB/USD/EUR, description ≤1024, metadata object ≤8 KiB, URL ≤2048, тело ≤32 KiB.
- `WEBHOOK_ALLOWED_DOMAINS` разрешает базовый домен и поддомены любой глубины, но не похожие домены.
- По умолчанию только публичный HTTPS:443, без redirects, credentials, fragment и environment proxy.
- Quorum queues payments.new/payments.dlq, exchanges payments/payments.dlx, publisher confirms и mandatory routing.
- Single-active-consumer, prefetch=1; Outbox relay использует FOR UPDATE SKIP LOCKED.
- Гарантия at-least-once; published Outbox автоматически не удаляется.
- Не коммитить изменения без запроса пользователя; не изменять существующий .gitignore без необходимости.

## Review Focus

1. Domain suffix confusion, IDNA, trailing dot и IPv4-mapped IPv6 не обходят allowlist/SSRF (Task 1, 5).
2. Два конкурентных POST с одним ключом создают ровно один Payment/Outbox; отличающееся тело даёт 409 (Task 2).
3. Confirm получен, но DB commit не состоялся: дубль безопасен; unroutable publish не помечается успешным (Task 3, 6).
4. Процесс умер после оплаты или после durable retry: повтор не проводит платёж и не теряет retry/DLQ (Task 4, 6).
5. Нет Content-Length, chunked body или webhook response бесконечны: память и время ограничены (Task 2, 5).
